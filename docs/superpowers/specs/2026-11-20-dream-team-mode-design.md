# 드림팀 모드 설계

2026-11-20 · 상태: 사용자 검토 대기

## 1. 의도와 이유

유튜브 영상 "AI 3대장 합체"(Claude Code가 지휘자, Codex·Antigravity가 직원)와
implaytips.com의 연결 프롬프트에서 출발했다. 사용자는 PowerCodeDeck 채팅 하나에서
**지휘자 AI가 대화 도중에 다른 AI를 직원으로 불러 일을 맡기고 결과를 받아 이어가는**
"드림팀"처럼 쓰고 싶다. 단, **전체 토큰(한도 사용량)을 혼자 쓸 때보다 늘리지 않는 것**이
조건이다. 이 저장소의 기존 원칙("측정 없이 절약을 주장하지 않는다", 토큰의 83%는
맥락 재읽기)이 그대로 적용된다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 아무 세션(Claude 또는 Codex 지휘자)에서나 대화 중에 드림팀 모드를 켜고 끌 수 있다.
- 켜져 있으면 지휘자가 직원(Codex, 다른 Claude 모델)에게 일을 맡기고 결과를 받는다.
- 위임마다 누가, 무엇을, 얼마의 비용으로 했는지 채팅에 보인다.
- agy(Antigravity)는 "복사해서 직접 붙여 넣는 직원"으로 참여한다.

**비목표**
- agy 자동 호출(허용 버튼 방식 포함). 약관 문제는 7장 참고.
- 이미지 생성, 유튜브 분석 같은 **앱 전용 기능의 자동화**. 대신 붙여 넣을 요청문을 만든다.
- 사이트 프롬프트처럼 AI가 래퍼 스크립트를 만드는 방식. 실행은 서버 코드가 맡는다.
- 별도 화면. 이 사용자는 기능을 채팅 안에 넣는 걸 선호한다(Runs 화면 제거 이력).

**반목표 (기술적으로 동작해도 실패로 본다)**
- 드림팀을 켰더니 같은 일을 할 때 한도가 눈에 띄게 더 빠진다.
- 꺼져 있는데 직원이 실행된다.
- Google 계정이 위험해지는 방식으로 agy를 실행한다.
- 측정하지 않은 "절약 N%"를 표시한다.

## 3. 제약

- **Antigravity 약관·FAQ (2026-11-20 재확인)**: `agy -p`는 직접 작성한 스크립트와 CI용이다.
  agy를 제3자 코딩 에이전트나 앱 안에 넣어 쓰는 것은 개인 요금제에서 허용되지 않는다
  (FAQ가 Claude Code를 이름으로 언급). 위반하면 계정 정지 사유가 된다.
  출처: antigravity.google/docs/faq, antigravity.google/terms §6.
- **`claude -p` + Fable**: 헤드리스 실행에서 Fable은 확인 없이 사용량 크레딧이 청구된다
  (multimodel-routing 조사). → Fable은 기본 직원 목록에서 뺀다.
- **Codex 사용량은 보고되지 않는다** (`auto_turns`에서 NULL). 비용은 "알 수 없음"으로 표시하고
  추정치를 만들지 않는다.
- 지휘자 CLI는 시작할 때만 MCP 도구 목록을 받는다. 도중에 도구를 추가하면 재시작이 필요하고,
  재시작하면 캐시가 식는다.

## 4. 접근 방식

| 방식 | 내용 | 장단점 | 결정 |
|---|---|---|---|
| A. 교대 근무 | 매 턴 한 명만 일하고, 기존 자동 라우팅으로 담당을 바꾼다 | 토큰은 가장 안전하지만 "부리는" 느낌이 없다. 사실상 기존 "자동" 세션이다 | 탈락 |
| **B. 외부 직원 호출** | 지휘자가 `pcd` MCP 도구로 다른 CLI를 별도로 실행하고 결과를 받는다 | 회사가 다른 AI(Codex)도 직원으로 둘 수 있고 영상과 가장 가깝다. 새 프로세스가 맥락을 다시 탐색해서 토큰이 늘 위험이 있다 → 5.4의 장치로 막는다 | **선택** |
| C. Claude 서브에이전트 팀 | Claude Code 자체 서브에이전트에 역할별 모델을 지정한다 | 토큰에 가장 유리하지만 Claude 밖의 AI를 쓸 수 없다 | 보류 (나중에 B와 함께 쓸 수 있음) |

사용자는 B를 골랐고 "모드로 따로 빼기"와 "아무 세션에서나 중간에 켜고 끄기"를 요구했다.

## 5. 설계 (결정된 부분)

### 5.1 켜고 끄기: 재시작 없는 토글
- 직원 호출 도구는 **모든 네이티브 Claude 세션**의 기존 `pcd` MCP 서버
  (`claude_driver.go:192`의 `--mcp-config`, 현재는 `approve` 도구 하나만 있음)에 **항상 등록**한다.
- Codex 세션에는 **실제 MCP 연결이 없다**. `codex_driver.go:486`의 `pcd connected`는 UI용 표시일 뿐이다.
  **v1에서 Codex 지휘자도 지원한다(사용자 결정).** 그래서 Codex 세션에도 실제 MCP 연결을 새로 만든다.
  - 설치된 `codex-cli 0.164.0`의 `codex app-server`는 `-c key=value` 설정 덮어쓰기를 지원한다.
    `CodexDriver.Start()`(`codex_driver.go:90`)가 `-c mcp_servers.pcd.command=<pcd 바이너리>`,
    `-c mcp_servers.pcd.args=[...]`를 붙여 Claude와 같은 `pcd` MCP 서버를 띄우는 방식을 1안으로 한다.
    프로세스를 시작할 때 들어가므로 "항상 등록, 재시작 없는 토글" 원칙과 맞는다.
  - 빌더가 확인할 것: (a) Codex가 MCP 도구 호출 전에 자체 승인을 요구하는지, 요구한다면
    `pcd` 서버의 두 도구만 자동 허용하는 설정이 있는지, (b) MCP 서버가 어느 에이전트의 호출인지
    알 수 있게 Claude 쪽과 같은 방식으로 에이전트 식별 정보를 넘길 것, (c) 로컬 모델(`oss:`) 세션에서도
    인수가 충돌하지 않는지.
  - `codex_driver.go:486`의 가짜 `pcd connected` 표시는 실제 연결 상태로 바꾼다.
  - Codex 지휘자의 직원 목록에서는 Codex 자신(같은 모델)을 뺀다. Claude Sonnet/Haiku가 기본 직원이 된다.
- 모드 상태는 **에이전트별로 DB에 저장**한다(`agents`에 컬럼 추가, 기본값은 꺼짐).
  도구가 호출되면 서버가 이 값을 확인하고, 꺼져 있으면 실행하지 않고
  "드림팀 모드가 꺼져 있음. 사용자에게 켜 달라고 하지 말고 직접 처리할 것"을 돌려준다.
- UI: 채팅 입력창 근처에 **👥 드림팀** 토글을 둔다. 토글은 서버 값만 바꾸고 CLI는 재시작하지 않는다.
- 토글을 켜면 다음 사용자 메시지 앞에 짧은 시스템 안내(팀 명단과 규칙, 수백 토큰)를
  한 번만 붙인다. 도구 설명 자체는 짧게 유지한다(항상 실리는 비용이므로).

### 5.2 지휘자와 직원
- **지휘자** = 그 세션의 CLI와 현재 모델. 따로 고르지 않는다. "자동" 세션처럼 턴마다 CLI나 모델이 바뀌면
  "자기 자신은 부르지 않기" 규칙은 **그 턴의 CLI·모델** 기준으로 적용한다.
- **직원 목록(기본값)**:
  - Codex (`codex exec`, 계정 기본 모델)
  - Claude Sonnet 5.5, Claude Haiku 5.5 (`claude -p`)
  - agy: **수동 전달 직원** (5.5)
  - Fable은 기본 목록에서 제외한다(3장). 사용자가 설정에서 명시적으로 켤 수 있다.
- 지휘자 자신과 같은 CLI·모델은 직원으로 부르지 않는다.
- 직원 목록은 전역 설정(Settings)에서 켜고 끈다. 세션별 명단은 이번 범위에 없다.

### 5.3 도구 모양 (MCP)
- `ask_member(member, task, files?)`: `member`는 직원 id, `task`는 지휘자가 쓴 요청서,
  `files`는 직원이 볼 상대 경로 목록(선택). 요약된 결과와 비용 정보를 돌려준다.
- `handoff_to_agy(task)`: 실행하지 않고 채팅에 "agy에게 맡길 일" 카드를 만든다. 5.5 참고.
- 실행은 기존 `RunProviders.NewRole` / `Delegator` 경로를 확장해서 쓴다.
- **`ask_member`는 결과가 나올 때까지 기다린다(동기 실행).** 지휘자가 같은 턴 안에서 결과를 이어 쓰는 게
  B의 핵심이라서다. 기존 Delegator처럼 다음 메시지 앞에 붙이는 비동기 방식은 쓰지 않는다.
  직원 타임아웃은 Claude CLI의 MCP 도구 타임아웃보다 짧게 잡는다(필요하면 지휘자 CLI 실행 시
  `MCP_TOOL_TIMEOUT`을 설정한다. 빌더가 설치된 버전에서 확인할 것). 기다리는 동안 채팅에는 진행 중인
  위임 카드가 보이고, 사용자의 중단(interrupt)은 직원 프로세스까지 종료한다. *(설계자 판단)*
- `mcp__pcd__ask_member`와 `handoff_to_agy`는 **지휘자의 승인 질문 없이 허용**한다. 모드를 켠 것을
  동의로 보고, 직원은 읽기 전용이기 때문이다(5.6). *(설계자 판단)*
- 기존 Delegator(긴 대화에서 어려운 요청에 조언 받기)는 v1에서 **그대로 따로 둔다**. 합치지 않는다. *(설계자 판단)*

### 5.4 토큰을 늘리지 않는 장치
1. **요청서만 전달**: 직원은 대화 전체가 아니라 지휘자가 쓴 요청서와 지정 파일 경로만 받는다.
2. **결과 길이 상한**: 직원 지시에 요약 상한을 넣고, 서버는 상한을 넘는 결과를 잘라
   "잘림" 표시를 붙인다(원문은 채팅 카드에서 펼쳐 볼 수 있지만 지휘자에게는 요약만 간다).
3. **직원 대화 이어 쓰기**: 같은 세션에서 같은 직원을 다시 부르면 그 직원의 이전 대화를
   resume해서 같은 파일을 다시 탐색하지 않게 한다. 대화 id는 기존 `agents.tool_sessions`와
   같은 방식으로 저장한다.
4. **상한**: 턴당 위임 횟수 상한과 세션당 직원 토큰 상한을 둔다. 넘으면 도구가 실행하지 않고
   "상한 도달(현재 사용량/상한). 사용자에게 알리고 직접 처리할 것"을 돌려준다. 동시에 채팅에
   **상한 카드**를 띄워, 사용자가 이번 세션만 상한을 올릴 수 있게 한다. 승인 대기로 막지 않는다
   (타임아웃 문제를 피하기 위해). Codex 직원은 토큰이 보고되지 않으므로 **횟수 상한만** 적용된다. *(설계자 판단)*
5. **비용 표시**: 위임 카드마다 직원, 소요 시간, 입력·출력 토큰(보고되면), 어느 구독인지를 보여준다.
   Codex는 "알 수 없음"으로 표시한다. 기록은 `auto_turns`와 같은 방식의 테이블에 남긴다.

### 5.5 agy 수동 전달 직원
- `handoff_to_agy`가 호출되면 채팅에 카드를 띄운다:
  `[📋 복사하고 agy 탭 열기]` `[결과 붙여넣기 ▸]`.
- 복사하기는 클립보드만 쓴다. PowerCodeDeck이 agy PTY에 **입력을 대신 넣지 않는다**
  (회색 지대이므로 금지).
- 사용자가 결과를 붙여 넣으면 다음 메시지로 지휘자에게 전달된다.
- agy 탭은 사용자가 직접 조작하는 일반 터미널 세션이다.

### 5.6 권한
- 직원은 기본적으로 **읽기 전용**으로 실행한다(Claude plan 모드, Codex read-only sandbox).
  지휘자와 같은 작업 트리에서 동시에 파일을 쓰는 충돌을 피하기 위해서다.
- 파일을 고쳐야 하면 직원은 변경안만 돌려주고, 실제 수정은 지휘자가 하면서
  기존 승인 흐름을 그대로 거친다.

### 5.7 앱 전용 기능
- 이미지 생성이나 유튜브 분석처럼 CLI에 없는 기능은 실행하지 않는다.
  지휘자가 "붙여 넣을 요청문"을 만들어 준다(5.5와 같은 카드 형태에 대상만 다름).

### 5.8 실패 처리 (사이트 프롬프트에서 가져온 것)
- 실제 응답을 받아야 성공으로 본다. 빈 응답, 시간 초과, 오류는 실패다.
- 실패 유형(미설치, 미로그인, 한도 소진, 네트워크, 타임아웃)을 구분해서 카드와 도구 결과에 담는다.
- 자동 재시도는 최대 1회다. 타임아웃이 나면 프로세스 그룹 전체를 종료한다.
- Settings의 직원 목록에 상태(사용 가능 / 로그인 필요 / 미설치)를 표시한다.
  기존 CLI 감지 기능을 쓰고, 한 문장 시험은 사용자가 버튼을 누를 때만 한다
  (자동 시험은 한도를 쓰므로).

### 5.9 "토큰을 늘리지 않는다"의 검증 (출시 전 관문)
- 같은 과제 2~3개를 **모드 끔 / 모드 켬**으로 실제 실행해서 Claude 쪽 사용량을 비교한다.
  과제는 예를 들어 "여러 파일을 읽고 요약한 뒤 한 곳을 고치기"처럼 위임할 만한 일이다.
- 출시 조건은 모드 켬의 Claude 한도 사용량이 모드 끔의 **110% 이하**인 것이다. Codex 사용량은 측정할 수 없으므로
  별도로 "알 수 없음 + 호출 횟수"로 보고한다. 결과는 이 문서 옆에 evidence 파일로 남긴다.
- 관문을 넘지 못하면 기본값(직원 목록, 상한)을 조정하거나 출시를 보류한다. 숫자를 지어내지 않는다. *(설계자 판단)*
- 실제 CLI 실행은 사용자 동의를 받고 한다(한도를 쓰므로).

## 6. 빌더에게 맡기는 것
- DB 컬럼 이름, 마이그레이션, 테이블 이름.
- 결과 상한, 턴당 횟수, 세션 토큰 상한의 구체적인 숫자. 처음에는 보수적으로 잡고 Settings에서 바꿀 수 있게 한다.
- 직원 실행 타임아웃(기존 Delegator는 5분).
- 카드 UI의 세부 디자인. 기존 Delegator 결과 카드와 모바일 레이아웃(iPhone Duo)을 깨지 않을 것.
- 도구 설명 문구. 짧게, 그리고 실제로 측정할 것.

## 7. 확인된 사실과 남은 위험
- `pcd` MCP는 현재 Claude 세션에만 실제로 연결돼 있다(`--mcp-config`, `mcp__pcd__approve`). Codex 연결은 이번 작업에서 새로 만든다(5.1).
- 항상 등록된 도구 설명이 실제로 차지하는 토큰은 아직 측정하지 않았다.
- PowerCodeDeck의 기존 agy 네이티브 채팅 드라이버와 v2 리뷰어의 agy 실행도 FAQ의
