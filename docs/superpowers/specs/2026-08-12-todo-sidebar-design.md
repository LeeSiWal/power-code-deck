# 할일 사이드 패널 설계

- 작성일: 2026-08-12
- 상태: 승인됨 (구현 대기)
- 선행: [할일 체크리스트 설계](2026-07-26-todo-checklist-design.md). 그 설계의 표면 A(스트립)·C(채팅 카드)·관제실 타일은 이미 있다. 이 문서는 **네 번째 표면**을 더한다.

## 배경

사용자 보고: "구현을 시작하면 얼마나 구현되었고 앞으로 얼마나 더 해야 하는지 가늠하기 어렵다. 목록을 옆에 띄워놓고 실시간으로 알고 싶다."

조사 결과 그 기능은 이미 출하돼 있었고 **작동한 적이 거의 없었다.** CLI가 체크리스트 도구를 `TodoWrite`(전체 스냅샷)에서 `TaskCreate`/`TaskUpdate`(델타)로 옮겼는데, 파서는 `TodoWrite`만 알고 있었다. 세션별 실측:

| 세션 | TodoWrite | TaskCreate |
|---|---|---|
| 07-16 18:00 | 9 | 0 |
| 07-20 02:05 | 12 | 3 |
| 07-20 13:14 | 0 | 5 |
| 07-23 22:17 | 0 | 5 |
| **07-26** | — | **v0.5.0 할일 체크리스트 출하** |
| 08-10 03:44 | 6 | 0 |
| 08-10 03:50 | 0 | 16 |
| 08-12 04:55 | 0 | 6 |

CLI는 07-20경 옮겨갔고 기능은 엿새 뒤 출하됐다. 즉 **출하 시점에 이미 입력이 끊겨 있었다.** 파서는 2026-08-12에 고쳤다(두 도구 모두 지원). 이 설계는 그 위에 올라간다.

따라서 이 문서의 범위는 새 데이터가 아니라 **새 화면 하나 + 서버의 지목 수정 하나**다.

## 확인된 사실

추측이 아니라 코드와 실제 트랜스크립트로 확인했다.

- **이어하기가 목록을 복원한다.** `poll()`은 따라가는 파일이 바뀌면 `offset=0`으로 되돌려 파일 전체를 재생한다. 이어하기는 새 에이전트를 `--resume <sid>`로 띄우고 같은 작업 디렉토리를 쓰므로(`handlers/sessions.go:109`, `services/agent.go:89`), 재개된 CLI가 기존 `<sid>.jsonl`에 이어 쓰는 순간 워처가 처음부터 재생해 목록을 되살린다. 실측: `5a9d1e62` 트랜스크립트 전체 재생 → `☑ 16/16` 복원.
- **그래서 영속화 테이블이 필요 없다.** 목록은 세션에 속하고, 세션은 이어받을 수 있다.
- **워처는 프로젝트 폴더의 최신 파일을 따라간다.** 워처는 에이전트별로 만들어지지만(`services/activity.go:55-57`) `dir`은 프로젝트 단위이고 `newestTranscript()`가 mtime 최신을 고른다. **한 프로젝트에 세션이 둘이면 서로의 목록을 본다.**
- **iPad는 이미 데스크톱 브랜치다.** `useDevice.ts:40-41`이 `w < 768`만 mobile로 보고, `TerminalPage.tsx:306`이 거기서 갈린다. 태블릿(768~1023)과 데스크톱은 같은 3열 레이아웃을 쓴다. 새 분기가 필요 없다.
- **우측 패널은 4탭 교체식이다.** 서브에이전트/브라우저/세션기록/동반셸. 탭을 고르면 내용이 교체되고, 같은 탭을 다시 누르면 패널이 닫힌다.

## 목표

- 계획을 세운 뒤 구현하는 동안, 찾아보지 않아도 남은 양이 보이게 한다
- 어떤 탭을 보고 있든 그 정보가 사라지지 않게 한다

## 비목표 (YAGNI)

- 사용자가 할일을 직접 편집·추가·체크하는 기능 — 이 목록은 여전히 에이전트의 것이다
- 프로젝트 단위 영속화 — 이어하기가 복원하므로 불필요하다. 게다가 안정적인 병합 키가 없다: 에이전트는 재계획 시 문구를 통째로 다시 쓴다(선행 설계서의 실측)
- 세션 간 할일 집계
- 서브에이전트 할일을 따로 보여주기
- 기존 좌우 스플리터의 터치 대응 — 같은 문제가 있지만 이번 범위 밖

## 1. 서버 — 트랜스크립트 지목

`ActivityManager.Start`에 세션 id **게터**(`func(agentID) string` → `agentSvc.ClaudeSessionID`)를 주입한다. 매 `poll()`이 조회해서:

- id가 있으면 → 그 폴더의 `<id>.jsonl`을 지목
- 비어 있으면 → 지금처럼 mtime 최신 (폴백)

값이 아니라 게터인 이유: id는 시작 시점에 없을 수 있다. 네이티브는 `system/init`이 와야 알고(`main.go:110`의 `SetPersistence`), 이어하기는 시작 시점에 안다(`handlers/sessions.go:120`).

### 수용하는 한계

터미널 트랙에서 **새로** 띄운 `claude`는 id를 배울 방법이 없다 — PTY 안의 CLI가 자기 트랜스크립트를 쓸 뿐 우리에게 알려주지 않는다. 그런 에이전트는 폴백 경로라 교차오염이 남는다. 네이티브가 기본이고 이어하기는 id를 갖고 오므로 실사용 대부분은 덮이지만, 전부 고쳐지는 것은 아니다. 이 문단이 그 사실의 기록이다.

## 2. 화면

### `TodoRows` (공용)

`TodoStrip`에서 목록 렌더링만 뽑아낸다. 글리프(`✓`/`▸`/`○`)·색·취소선·`in_progress`일 때 `activeForm`을 쓰는 규칙이 여기 한 곳에 있어야 세 표면이 같은 목록으로 읽힌다. `TodoStrip`은 이걸 쓰도록 바꾼다 — 동작 변화 없음.

### `TodoPanel`

우측 패널의 탭 콘텐츠 **위에 고정**. 헤더는 `☑ 3/7`, 본문은 항상 펼쳐진 `TodoRows`. 탭을 바꿔도 남는다 — 이것이 "항상"의 정의다.

탭으로 넣지 않는 이유는 선행 설계서가 우측 탭을 거부한 이유와 같다: 열어야 보이는 것은 "찾아보지 않아도 알게 한다"는 목적을 스스로 무너뜨린다. 5번째 탭이면 동반 셸을 여는 순간 사라진다.

**할일이 없으면 통째로 렌더하지 않는다.** 빈 껍데기는 공간만 먹고 아무것도 알려주지 않는다.

### 가로 스플리터

`TodoPanel`과 탭 콘텐츠 사이. 높이는 `localStorage: pcd:panel:todos`에 기억한다. 최소 72px, 최대 패널 높이의 70% — 고정 구역이 탭을 완전히 밀어내지 못하게 한다.

**좌우 스플리터를 복사하지 않는다.** 기존 것은 `mousedown` 기반인데(`TerminalPage.tsx:253`) 이 패널의 대상 기기에 iPad가 포함된다. 이번 스플리터는 **Pointer Events**로 만들어 마우스·터치·펜을 함께 받는다. 드래그는 기존과 같이 RAF로 스로틀하고 놓을 때 저장한다.

## 3. 표면별 동작

| 상황 | 보이는 것 |
|---|---|
| 우측 패널 열림 | `TodoPanel` 전체 목록 (항상 펼침) |
| 우측 패널 닫힘 / 줌 | 중앙 `TodoStrip`이 `☑ n/m` 유지 |
| 모바일 (<768px) | 기존 `TodoStrip` 그대로 — 변경 없음 |
| 할일 없음 | 어느 표면도 렌더하지 않음 |

숫자는 어떤 상태에서도 잃지 않고, 잃는 것은 상세뿐이다. 모바일에 사이드바를 넣지 않는 이유는 자리가 없기 때문이고, 바텀시트로 대체하지 않는 이유는 **열어야 보이기 때문**이다 — 폰에는 이미 탭 없이 항상 뜨는 스트립이 있어 그쪽이 더 낫다.

## 4. 에러 처리

- 활동 스냅샷에 `todos`가 없거나 비면 렌더하지 않는다 (기존 규칙 유지)
- 지목한 `<id>.jsonl`이 아직 없으면 폴백(최신 파일)을 쓴다 — 세션 시작 직후 파일이 생기기 전 구간
- 저장된 높이가 범위를 벗어나면 기본값으로 잘라 쓴다 (기존 `readPanelWidth`와 같은 방식)

## 5. 검증

- 서버 단위 테스트: id가 있으면 그 파일을 지목, 없으면 최신 폴백, 지목한 파일이 없으면 폴백
- 서버 회귀 테스트: 한 프로젝트의 두 에이전트가 서로의 목록을 보지 않는다
- `cd server && CGO_ENABLED=0 go build ./... && go test ./...`
- `cd client && ./node_modules/.bin/tsc --noEmit`
- 실물 확인:
  - 계획을 세우는 세션에서 패널이 실시간으로 차오르는가
  - 탭(동반 셸 등)을 바꿔도 할일 구역이 남는가
  - **iPad에서 터치로** 높이가 조절되는가 — 마우스 전용이면 이 표면은 대상 기기의 절반에서 못 쓴다
  - 패널을 닫으면 중앙 스트립이 숫자를 유지하는가
  - 할일 없는 세션에서 아무것도 안 뜨는가
  - 한 프로젝트에 세션 둘을 띄우고 서로의 목록이 섞이지 않는가
- `dist/pcd.exe` 재빌드 (클라이언트 변경)

## 6. 리스크

| 리스크 | 대응 |
|---|---|
| CLI가 체크리스트 도구를 또 바꾸면 조용히 빈 목록이 된다 | 이미 한 번 일어났다. 도구 이름을 상수로 두고(`toolTodoWrite`/`toolTaskCreate`/`toolTaskUpdate`) 두 계열을 모두 지원한다. 타입 검사로는 안 잡히므로 실물 확인 항목에 남긴다 |
| 고정 구역이 서브에이전트 애니메이션을 눌러 답답해진다 | 높이를 사용자가 조절하고 기억한다. 최대 70%로 탭이 완전히 밀리지 않게 막는다 |
| 터미널 트랙 교차오염이 남는다 | 수용한다(§1). 네이티브가 기본이고 이어하기는 id를 갖고 온다 |
