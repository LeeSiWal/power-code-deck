# 데스크탑앱 · 원격 서버 · LLM 배치 설계

- 작성일: 2026-08-21
- 상태: 설계 (미구현)
- 결정: 데스크탑 셸은 **Tauri v2**, 착수는 이 문서부터
- 관련 코드: `server/services/handoff.go`, `server/middleware/hostcheck.go`, `server/services/intelligence.go`
- 관련 문서: [Local Intelligence POC 리포트](../../local-intelligence-poc-report.md) — **§6·§7의 "BLOCKED"는 이 문서로 갱신된다**

## 배경

"웹 말고 데스크탑앱으로도", "원격으로 서버를 붙여서", "LLM은 로컬 자원이나 별도 서버로 —
그렇게 토큰을 세이브" 세 가지가 같이 들어왔다. 정리하면 축이 셋이다.

| 축 | 무엇 | 배치 후보 |
|---|---|---|
| **A. 워크스페이스 호스트** | 소스 + Claude/Codex 런타임 + pcd 서버 | 내 PC / 원격 서버 |
| **B. 클라이언트 셸** | 화면 | 데스크탑 / 모바일 / 브라우저 |
| **C. LLM 프로바이더** | 컨텍스트 압축용 로컬 모델 | 워크스페이스 호스트 / 내 PC / 별도 GPU 박스 |

**A는 쪼개지지 않는다.** Claude Code와 Codex는 파일이 있는 곳에서 돈다 — 소스는 서버에 두고
런타임만 내 PC에서 돌리려면 네트워크 마운트나 동기화가 필요하고, 둘 다 이 앱이 감당할 물건이 아니다.
`CodexDriver`가 저장소 cwd로 `codex app-server --stdio`를 띄우는 구조가 이미 그 사실을 굳혔다.

그래서 "PC면 그 컴퓨터 것, 아니면 서버 것"은 **선택이 아니라 귀결**이다. 이건 설계를 단순하게 만든다:
소스·런타임·pcd 서버·파일 API가 한 덩어리로 움직이고, 그 덩어리를 **워크스페이스 호스트**라 부른다.
모바일은 로컬 호스트가 없으므로 항상 원격, 데스크탑은 로컬(사이드카) + 원격 N개다.

**진짜 독립 축은 C 하나뿐이다.** 그리고 C가 이 설계에서 가장 어려운 부분이다 — 아래 5절.

## 확인된 사실

추측이 아니라 코드와 **프로덕션 DB 실측**으로 확인했다.

### 클라이언트는 same-origin을 하드코딩하고 있다

- `client/src/lib/api.ts:1` — `const API_BASE = '/api'`
- `client/src/lib/ws.ts:63` — `${protocol}//${location.host}/ws?token=…`
- `client/src/lib/api.ts:149,163` — 핸드오프 교환·익명 토큰이 `credentials: 'same-origin'`
- `client/src/lib/api.ts:281` — `/api/files/raw` 를 fetch로 직접 조립 (Bearer 수동 첨부)
- `client/src/components/browser/BrowserPanel.tsx:47` — `/api/proxy` 를 apiFetch를 거치지 않고 직접 호출
- `client/src/lib/push.ts:40` — `navigator.serviceWorker.register('/sw.js')`, 등록은 `main.tsx:21`

### 서버 태세도 대칭으로 same-origin에 맞춰져 있다

- `config.go:165` `AllowedOrigins()` — 루프백 4종은 항상, 그 외는 `PUBLIC_URL`/`LAN_URL`/`CORS_ORIGINS`가 있어야 추가
- `config.go:190` `AllowedHosts()` — DNS 리바인딩 가드. 비루프백 Host는 명시 설정 시에만
- `ws/hub.go:50` `checkOrigin` — **Origin 헤더가 없으면 통과**시킨다(CLI용). 데스크탑 셸에는 유리하지만 의도된 설계는 아니다
- `auth/ws_auth.go` — WS 토큰은 **쿼리스트링**으로 전달된다

### 토큰에 기기 신원도 폐기 수단도 없다

- `auth/auth.go:51` access 7일 / `:61` refresh 30일 / `:117` 핸드오프 쿠키 30분
- 전부 단일 `JWT_SECRET` HS256 서명이고, jti도 화이트리스트도 없다.
  **기기 하나만 끊으려면 시크릿을 돌려야 하고, 그러면 전부 로그아웃된다.**
- `deviceId.ts`의 device id는 localStorage 랜덤값으로 **푸시 타겟팅·세션 독점용이지 인증 요소가 아니다**
- 핸드오프 상환은 **httpOnly 쿠키**를 심는다(`auth.go:117`). 크로스오리진 데스크탑은 이 흐름을 그대로 못 쓴다

### Local Intelligence 실측 — POC 리포트가 낡았다

리포트 §6은 원격 프로바이더 E2E를 `BLOCKED`로 적었지만, **실제로는 돌고 있다.**
프로덕션 DB(`~/PowerCodeDeck/powercodedeck.db`)에 프로바이더가 설정돼 있고 트레이스 18건이 쌓였다.

- 프로바이더: `Mac Studio` / ollama / `http://192.168.1.22:11434` / `qwen3-coder:30b` / timeout 180s

| | 건수 | raw 추정토큰 | 결과 |
|---|---|---|---|
| 성공 | **8** | 12,538 – 14,543 | opt 388–612, **감축 95.4–97.3%**, 지연 38–59초, localTokens 16.8k–19.0k |
| 로컬 실패 | **8** | 32,761 – 37,434 | 3건 30초 `LOCAL_TIMEOUT`, 5건 125초 `LOCAL_PROVIDER_UNREACHABLE` |
| 클라우드 실패 | 2 | — | `CLOUD_EXECUTION_FAILED` (로컬 축과 무관) |

**성공과 실패가 raw 크기로 완벽히 갈린다.** 성공 중앙값 14,535 / 실패 중앙값 34,379,
겹치는 구간이 하나도 없다. 즉 이 기능은 **작은 컨텍스트에서만 동작하고, 가장 도움이 될 큰 컨텍스트에서 항상 죽는다.**

세부 사실 셋:

1. **125초 실패는 `UNREACHABLE`이 아니다.** 이벤트 사유가 전부
   `Post "http://192.168.1.22:11434/api/generate": context canceled` 다 — 도달 실패가 아니라
   **부모 컨텍스트 취소**다. `handlers/intelligence.go:69`가 `svc.Run(r.Context(), …)`로
   **HTTP 요청 컨텍스트를 그대로 넘기기 때문**에, 브라우저나 리버스 프록시가 요청을 끊으면
   로컬 추론이 통째로 취소된다. 작업트리의 미커밋 diff가 `ErrRequestCanceled`를 추가하는 중인데,
   그건 **분류를 고치는 것이지 원인을 고치는 게 아니다**(5절).
2. **미커밋 diff는 입력을 줄여 시간예산에 맞추는 중이다** — `maxContextBytes` 192KB→64KB,
   `maxFileBytes` 24KB→12KB. 주석이 이유를 밝힌다: *"a 30B local model can finish before common
   reverse-proxy request deadlines."* 옳은 대응이지만 **상한을 낮추는 대응**이다.
3. **로컬이 19k 토큰을 태워 14.5k를 500으로 줄인다.** 클라우드 토큰과 로컬 토큰은 값이 다르므로
   그 자체로는 문제가 아니다. 문제는 베이스라인이다 — 아래.

### 감축 96%는 존재한 적 없는 베이스라인과의 비교다

`CLOUD_ONLY`는 사용자 작업을 **바이트 그대로** 네이티브 세션에 넘긴다(리포트 §8이 회귀테스트로 고정).
즉 `raw_tokens`(pcd가 조립한 후보 컨텍스트)는 **애초에 클라우드로 전송되지 않는 값**이다.
따라서 `raw − optimized`는 절감액이 아니다. 실제 절감은
`(Codex가 스스로 파일을 읽었을 토큰) − (500토큰 팩 + 그래도 검증하러 읽는 토큰)`이고,
게다가 클라우드 프롬프트가 팩을 *"advisory, verify it against the repository"*로 명시하므로
Codex는 어차피 다시 읽는다. 리포트 §11도 같은 한계를 적어뒀다("Codex's hidden internal context/token usage").

**이 문서는 절감을 부정하지 않는다. 측정된 적이 없다고 말한다.** 3축 라우팅을 설계하기 전에
이걸 한 번 재는 게 순서다(9절).

### 이미 갖춰져 있어 재사용할 것

- 일회용 토큰 + QR 전체 흐름 (`services/handoff.go` — 원문 미저장, SHA-256 해시, 재발급 시 이전 것 무효화)
- LAN 오리진 자동 채택 (`main.go:48`, `services.DetectLANIP`)
- 서버가 클라이언트를 내장한 단일 바이너리 (`main.go:31` `//go:embed all:static`) — 사이드카로 그대로 쓸 수 있다
- WS 재연결·전송 큐·포그라운드 복귀 처리 (`ws.ts`)
- 프로바이더 레지스트리 + 4단계 헬스체크 + 트레이스 (`services/intelligence.go`)

## 목표

- 브라우저든 데스크탑이든, **여러 워크스페이스 호스트**를 하나의 클라이언트에서 오간다
- 데스크탑앱은 터미널을 열지 않고 로컬 호스트를 띄운다
- 원격 노출 시 인증이 **기본값으로** 켜지고, 기기 단위로 끊을 수 있다
- LLM 프로바이더가 워크스페이스 호스트와 **다른 기계**에 있어도 성립한다
- 클라이언트 코드베이스는 **하나로 유지**한다

## 비목표 (YAGNI)

- **자체 릴레이/브로커 서버** — 사용자당 서버가 1개인 구조에서 얻는 게 없고, 가용성·과금·프라이버시 책임만 생긴다
- **중앙 집계 서버** — 다중 호스트 집계는 클라이언트 팬아웃으로 한다(7절)
- **범용 LLM 역프록시** — 클라이언트를 통해 임의의 LLM 트래픽을 터널링하지 않는다. 필요한 건 단계 하나뿐이다(5절)
- **자동 라우팅·비용 추적** — POC 리포트 §12의 판단을 유지한다. 절감을 재기 전에는 만들지 않는다
- **소스 동기화·네트워크 마운트** — A축이 쪼개지지 않는다는 결론의 직접 귀결
- **계정·다중 사용자** — 여전히 1인 1덱이다. "기기"는 늘지만 "사람"은 안 는다
- **모바일 네이티브 앱** — 웹/PWA로 충분하다
- **리눅스 데스크탑 패키징** — 1단계 제외(10절)

## 1. 엔드포인트 추상화 — 이 설계의 load-bearing 작업

**이것 하나가 데스크탑-원격과 브라우저-크로스오리진을 동시에 연다.** 반대로 이걸 건너뛰고
셸부터 만들면 셸 안에서 프록시로 우회하게 되고, 그 순간 로컬 전용 데스크탑앱에 갇힌다.

`lib/endpoint.ts` 를 신설한다.

```
Endpoint = { id, label, baseUrl, wsUrl, auth: {kind, token}, capabilities }
```

- `baseUrl`이 비면 **현재 오리진** — 오늘의 동작이 기본값으로 보존된다
- `api.ts`의 `API_BASE` 상수를 이 값의 조회로 바꾼다
- `ws.ts:63`의 `location.host`를 `endpoint.wsUrl`로 바꾼다
- `api.ts:281`(files/raw)과 `BrowserPanel.tsx:47`(proxy)처럼 apiFetch를 우회하는 곳을 전부 걷어낸다 — **이 두 곳이 새는 지점이다**
- `push.ts:40`의 서비스워커는 오리진에 묶인다. 원격 호스트에서는 웹푸시가 성립하지 않으므로
  `capabilities.webPush = false`로 내리고, 데스크탑에서는 네이티브 알림으로 대체한다(6절)

토큰 저장도 호스트별로 쪼개진다. `localStorage['accessToken']` 단일 키는 `pcd:endpoints` 아래
호스트별 레코드가 된다. `api.ts:118`의 `window.location.href = '/login'`도 "이 호스트가 재인증 필요"
상태로 바뀌어야 한다 — 원격 하나가 만료됐다고 앱 전체를 로그인 화면으로 던지면 안 된다.

### 수용하는 한계

호스트 전환은 **전체 재구독**이다. WS 하나에 여러 호스트를 태우지 않는다.
관제실만 예외로 다중 소켓을 연다(7절).

## 2. 크로스오리진 서버 태세

지금 CORS·HostCheck·CheckOrigin은 셋이 각자 판단하고, 셋 다 same-origin 전제다.
`main.go:38-48`의 LAN 자동 채택 주석이 남긴 교훈 — **가드끼리 어긋나면 "페이지는 뜨는데 붙지는 않는" 상태**가 된다 —
가 여기서 그대로 반복될 수 있다.

- `CLIENT_ORIGINS` 개념을 명시적으로 도입하고, 세 가드가 **하나의 소스**에서 파생되게 한다
- 데스크탑 셸의 Origin(`tauri://localhost`, 윈도우 `https://tauri.localhost`)을 기본 허용 목록에 넣는다.
  `checkOrigin`의 "빈 Origin 통과"에 의존하지 않는다 — 그건 CLI용 예외지 설계된 경로가 아니다
- `credentials: 'same-origin'` 두 곳(`api.ts:149,163`)을 헤더/토큰 기반으로 바꾼다
- CORS 프리플라이트에 `Authorization`이 이미 들어 있다(`cors.go`) — 그대로 쓴다

### WS 토큰을 쿼리에서 뺄지

`ws_auth.go`는 토큰을 쿼리스트링에서 읽는다. 리버스 프록시 액세스 로그에 남는다.
브라우저 WebSocket API는 커스텀 헤더를 못 붙이므로 바꾸려면 서브프로토콜 트릭이 필요하다.
지금의 차단 요소는 아니지만, T2(공개 도메인) 문서에 "액세스 로그에 토큰이 남는다"를 명시해야 한다.

## 3. 인증 — 노출도에서 파생되고, 기기 단위로 끊긴다

현재 기본값은 인증 없음이고 그걸 루프백 바인딩 + HostCheck가 방어한다.
**원격이 열리는 순간 그 방어가 사라진다.**

1. **노출도 파생** — 루프백 밖으로 열려 있는데(`BIND_HOST`가 비루프백이거나 `PUBLIC_URL` 설정)
   `auth=none`이면 **기동을 거부**한다. 명시적 강제 플래그로만 뚫린다.
2. **기기 자격증명** — 토큰에 `jti` + `device` 클레임을 넣고 서버에 기기 테이블을 둔다.
   기기 목록·마지막 접속·개별 폐기가 설정 화면에 뜬다.
   **폐기가 시크릿 로테이션을 뜻하지 않게 되는 것**이 핵심이다.
3. **페어링은 기존 것을 재사용** — 서버에서 `pcd pair` → QR/코드 → 데스크탑이 상환해 기기 자격증명 획득.
   차이는 하나: 상환 결과가 **세션 범위 httpOnly 쿠키가 아니라 앱 범위 기기 토큰**이라는 것.

## 4. 원격 전송 — 코드가 아니라 문서

| 티어 | 방식 | 우리 작업 |
|---|---|---|
| T1 LAN | `http(s)://<lan-ip>:<port>` | 거의 완료 (`LAN_HANDOFF_ENABLED` + `DetectLANIP`) |
| T2 도메인 | Caddy/nginx + `PUBLIC_URL` | 문서 + WS 유휴 타임아웃·버퍼링 주의사항 |
| T3 무설정 원격 | **Tailscale** | 문서만. 코드 0 |

Tailscale을 권하는 이유가 5절 때문에 하나 더 늘어난다: **워크스페이스 호스트와 GPU 박스를
같은 메커니즘으로 서로 도달 가능하게 만든다.** 두 문제를 한 도구로 푼다.

## 5. LLM 축 — 이 설계에서 가장 어려운 부분

### 5.1 방향 문제

`intelligence.go`의 두 단계는 **서로 다른 기계를 요구한다.**

- `BuildCandidateContext(ctx, agent.WorkingDir, task)` — **소스가 있는 곳**에서 돌아야 한다 (= 워크스페이스 호스트)
- `providers.ollamaGenerate(ctx, p, …)` — 워크스페이스 호스트가 `p.BaseURL`로 **다이얼 아웃**한다

즉 프로바이더는 **워크스페이스 호스트에서 도달 가능**해야 한다. 배치별로:

| 워크스페이스 | LLM 위치 | 되나 |
|---|---|---|
| 내 PC(사이드카) | 같은 PC | ✅ localhost |
| 내 PC | LAN GPU 박스 | ✅ 오늘 돌고 있는 구성 (`192.168.1.22`) |
| 원격 서버 | 그 서버 | ✅ |
| 원격 서버 | GPU 박스 (Tailscale 등으로 도달 가능) | ✅ |
| 원격 서버 | **내 노트북 (NAT 뒤)** | ❌ **서버가 다이얼할 수 없다** |

마지막 줄이 "유저 PC의 자원으로 토큰을 세이브"의 정확한 실패 지점이다.

**v1 결정: 요구조건으로 문서화한다.** 프로바이더는 워크스페이스 호스트에서 도달 가능해야 하고,
Tailscale이 대부분의 경우를 만족시킨다. 코드 0.

**v2 (필요가 확인되면): 컨텍스트팩 단계만 클라이언트로 내린다.** 서버가 후보 컨텍스트를 만들어
클라이언트에 주고, 클라이언트가 자기 ollama로 압축해 되돌려준다. 페이로드는 이미 64KB로 묶여 있고
(미커밋 diff), 데이터는 클라이언트가 이미 볼 권한이 있는 파일 내용이라 **새 보안 경계가 생기지 않는다.**
정책·트레이스·폴백은 서버에 남는다. **범용 LLM 역프록시는 만들지 않는다** — 필요한 건 단계 하나다.

### 5.2 잡(job)으로 만들어야 한다 — 실측이 요구하는 변경

`handlers/intelligence.go:69`가 `svc.Run(r.Context(), req)`로 HTTP 요청 컨텍스트를 넘긴다.
그래서 **브라우저나 프록시가 요청을 끊으면 로컬 추론이 죽는다.** 실측 125초 실패 5건이 이것이다.

로컬 추론은 성공해도 38–59초가 걸린다. 이걸 HTTP 요청 하나에 매달아두는 건 LAN에서도 아슬아슬하고,
원격에서는 성립하지 않는다 — 리버스 프록시 기본 타임아웃, 모바일 화면잠금, 셀룰러 전환이 전부 요청을 끊는다.
미커밋 diff의 `ErrRequestCanceled`는 **이 실패를 정확히 이름 붙이지만 없애지는 않는다.**

바꿀 것:

- `POST /api/intelligence/run`은 **즉시 trace id를 반환**한다
- 실행은 요청과 분리된 컨텍스트에서 돈다. 취소는 사용자의 명시적 취소일 때만
- 진행 상황은 **이미 있는 WS 허브**로 밀어준다 (`intelligence:trace` 이벤트) — 새 전송로가 필요 없다
- 완료 시 클라우드 디스패치는 서버가 한다. 이미 `dispatchCloud`가 서버 안에 있으므로 구조 변경이 아니다

이러면 부수 효과로 **모바일에서 실행을 걸고 화면을 꺼도 된다.** 원격 시나리오에서 이건 요구사항이지 보너스가 아니다.

### 5.3 크기 상한을 정직하게 노출한다

성공/실패가 raw 14.5k vs 34.4k로 완벽히 갈린다. 미커밋 diff가 `maxContextBytes`를 64KB로 낮춘 건
이 경계 안으로 들어가려는 것이고, 옳다. 다만 그 결과를 **사용자에게 숨기지 않아야 한다** —
후보 컨텍스트가 상한에 걸려 잘렸으면 트레이스와 UI에 그대로 뜨게 한다.
"96% 줄었습니다"만 보이고 "그런데 파일 절반은 안 봤습니다"가 안 보이면 그 숫자는 사용자를 오도한다.

### 5.4 프로바이더 설정은 호스트별이다

`local_ai_providers`는 워크스페이스 호스트의 SQLite에 있다. 호스트가 여럿이면 같은 GPU 박스를 N번 등록하게 된다.
**그대로 둔다** — 도달성은 실제로 호스트마다 다르다(`192.168.1.22`는 특정 LAN에서만 유효하다).
대신 클라이언트가 프로바이더 설정을 호스트 간에 복사할 수 있게 하고, 헬스 결과를 호스트별로 보여준다.

## 6. 데스크탑 셸 (Tauri v2)

### 왜 데스크탑앱인가 — 이 목록이 셸 코드의 범위를 정한다

- **네이티브 알림.** 웹푸시는 VAPID + 서비스워커 + HTTPS를 전부 요구하고(`services/webpush.go`, `lib/push.ts`),
  서비스워커가 오리진에 묶여 원격 호스트에서는 성립조차 안 한다. **원격에서 가장 큰 이득이 여기다.**
- **로컬 호스트 자동 기동.** 터미널을 열 필요가 없어진다
- 트레이 상주 + 전역 단축키 → "승인 대기 중인 세션으로 즉시 점프"
- 사파리 백그라운드 프리즈(`ws.ts` 생성자에 이것 때문에 짠 코드가 있다)·localStorage 축출에서 해방
- 딥링크(`pcd://`), 네이티브 파일 다이얼로그, 자동 업데이트
- (5.1 v2를 하게 되면) **클라이언트 로컬 ollama 접근** — 브라우저는 CORS 때문에 못 한다

### 구조

```
Tauri 셸
├── 사이드카: pcd (기존 바이너리 그대로) → 127.0.0.1:<랜덤포트>
├── 웹뷰: 같은 React 번들
└── platform 어댑터 (notify / openExternal / pickFile / secureStorage / spawnLocal)
```

**가장 큰 리스크는 기술이 아니라 클라이언트 포크다.** React 코드베이스 하나 + 셸 3개,
그 사이에 얇은 `platform` 어댑터 하나. 어댑터는 브라우저 구현이 항상 먼저 있고 데스크탑이 그것을 대체할 뿐이다.
기기 토큰은 localStorage가 아니라 OS 키체인에 둔다.

## 7. 원격에서 의미가 바뀌는 것들

**첨부 파일.** 업로드는 서버 쪽 `.pcd-attachments/`에 쓰고 상대경로를 돌려준다(`handlers/files.go:242`).
로컬 파일을 원격 세션에 떨구면 "경로 참조"가 아니라 반드시 "전송"이다.
데스크탑에서 로컬 호스트에 떨굴 때만 경로 참조가 성립한다.

**DB가 호스트마다 따로다.** 알림·할일·승인규칙·프로바이더·트레이스가 전부 호스트 SQLite에 있다.
원격의 킬러 기능은 **"기계 세 대의 에이전트를 한 벽에서 보는 관제실"**이고, 이건 클라이언트 팬아웃으로 합친다.
타일에 출처 호스트를 표시한다. 승인 카드도 마찬가지다 —
**어떤 기계에서 무엇을 허용하는지 모르면 승인 게이트의 존재 이유가 사라진다.**

## 9. 검증

**0단계 — 절감 측정.** 같은 저장소, 같은 비파괴 작업으로 `CLOUD_ONLY` / `LOCAL_PREPROCESS_CLOUD`를
각각 N회 돌리고, **Codex가 실제로 소비한 토큰**을 양쪽에서 비교한다. `raw − optimized`가 아니다.
(리포트 §9의 Codex 스모크가 `Reported tokens: 4,423`을 남긴 걸 보면 수치를 얻을 경로는 있다.)
절감이 지연 38–59초를 정당화하지 못하면 5절 전체가 재검토 대상이다.

- 1단계: 서버 A를 `BIND_HOST=0.0.0.0`으로 띄우고 **다른 오리진에서 서빙한 클라이언트**로 붙는다.
  터미널 입출력·네이티브 채팅·파일 raw·프록시·업로드 — **새는 곳이 이 다섯이다**
- 가드 정합성 테스트: 같은 설정에서 **세 가드가 같은 판단**을 하는지 고정. `main.go:38-48`이 남긴 교훈을 테스트로 못 박는다
- 2단계: 실행 중 브라우저 탭을 닫고 → 트레이스가 계속 진행되고 클라우드 디스패치까지 가는지.
  **오늘은 이 시나리오가 125초 실패로 끝난다**
- 3단계: 기기 폐기 후 그 기기의 access·refresh가 모두 죽고 **다른 기기는 살아 있는지**
- 4단계: 사이드카 강제종료 → 셸이 재기동하는지. 원격 링크 단절 → 재연결 시 스크롤백 복원
  (512KB 링버퍼가 과거에 물었던 자리다)

## 10. 리스크

- **절감이 측정되지 않았다.** 이 문서에서 가장 큰 미지수. 0단계가 이걸 먼저 없앤다
- **로컬 추론 지연 38–59초.** 대화형 흐름에 그대로 얹으면 사용자가 안 쓴다. 잡 전환(5.2)이 완화하지만 없애지는 못한다
- **리눅스 WebKitGTK 파편화.** 완화: 1단계 타깃은 Windows/macOS. 커스텀 DOM 렌더러가 WebKit에서 검증된 건
  아이패드 사파리 한 버전대일 뿐 WebKitGTK 전 버전이 아니다
- **클라이언트 포크.** 어댑터 경계를 코드리뷰에서 지킨다
- **원격 인증을 만들면서 로컬 무인증의 편의를 잃는 것.** 노출도 파생(3절)이 막는다 — 루프백만 쓰는 사람은 아무것도 달라지지 않아야 한다
- **`checkOrigin`의 빈 Origin 통과에 기대는 것.** 편하지만 나중에 그 예외를 못 막게 만든다. 명시 허용으로 간다
