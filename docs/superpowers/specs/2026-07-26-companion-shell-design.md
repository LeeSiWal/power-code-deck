# 동반 셸 (Companion Shell) 설계

- 작성일: 2026-07-26
- 상태: 승인됨 (구현 대기)

## 배경

Claude 세션이 네이티브 챗으로 바뀌면서 **직접 명령을 쳐볼 수단이 사라졌다.** `git status`를 한 번 확인하거나 빌드를 돌려보려면 Claude에게 시켜야 하고, 그건 승인 흐름과 대화 기록을 통과한다.

터미널 트랙 자체는 온전하다 — `?terminal` 폴백(`TerminalPage.tsx:44`)이 남아 있고 세션 엔진도 셸용으로 유지하기로 로드맵에 명시돼 있다. 다만 그것은 **에이전트를 PTY TUI로 띄우는** 경로이지 네이티브 챗 옆에 셸을 두는 것이 아니다. `?terminal`을 쓰면 네이티브 챗을 통째로 포기하게 된다.

## 확인된 사실

**① 세션 엔진은 에이전트와 무관하게 설계돼 있다.**

`CreateSessionRequest`의 주석이 명시한다 — *"ID is chosen by the caller (PowerCodeDeck uses the agent id) so the session id == agent id everywhere"*. `SessionInfo`도 *"durable agent metadata (name, color, …) stays in the AgentService/DB"*라고 선을 긋는다.

즉 **에이전트 결합은 서비스 계층의 관례이지 엔진의 요구가 아니다.** 임의의 ID로 세션을 만들면 스크롤백 링버퍼, attach/detach, resize, ACK 기반 flow control이 모두 그대로 따라온다.

**② 한 연결은 한 세션만 본다.**

`client.watchingAgent`는 단일 문자열이다(`ws/client.go:22`). `attachCount`(`ws/client.go:37`)는 *같은* 에이전트를 보는 여러 UI 표면을 세는 것이고(대시보드 썸네일과 터미널이 소켓 하나를 공유하던 문제), **서로 다른 두 세션을 동시에 보는 경로는 없다.** 다른 세션에 attach하면 기존 것을 정리한다(`ws/hub.go:670`).

**③ 엔진 세션은 관제실에 자동으로 뜨지 않는다.**

`pollStatus`·`pollMeta`가 `engine.List()`가 아니라 `agentSvc.List()`(DB)를 순회한다. DB 행이 없는 세션은 요약에 잡히지 않으므로 **별도의 숨김 처리가 필요 없다.**

## 목표

- 네이티브 챗을 유지한 채, 같은 작업 디렉토리에서 명령을 직접 실행할 수 있게 한다
- 패널을 닫거나 다른 화면을 다녀와도 출력과 현재 디렉토리가 유지된다
- 데스크톱·태블릿·모바일 모두에서 쓸 수 있게 한다

## 비목표 (YAGNI)

- 셸을 여러 개 띄우기 (에이전트당 하나)
- 셸의 기기 간 배타 소유·핸드오프 (에이전트 세션의 개념이지 스크래치 셸의 개념이 아니다)
- 셸을 관제실에 노출하기
- 셸 출력의 영구 저장·검색 (엔진의 링버퍼가 스크롤백을 담당한다)
- 유휴 타임아웃 (§3 참고)

## 결정 요약

| 항목 | 결정 |
|---|---|
| 세션 생성 | 기존 엔진, ID는 `shell:<agentId>` |
| 전송 | **별도 `shell:*` 이벤트 채널** (`watchingAgent` 미사용) |
| 수명 | 유지. 유휴 타임아웃 없음. 명시적 종료 + 에이전트 삭제 시 동반 종료 |
| 데스크톱·태블릿 | 우측 패널 4번째 탭 |
| 모바일 | 하단 바텀시트 (Files·Browser·Sessions와 같은 패턴) |

## 1. 서버 — 엔진 재사용

```
CreateSessionRequest{
    ID:      "shell:" + agentId,
    Type:    "shell",
    Cwd:     <에이전트의 작업 디렉토리>,
    Command: <사용자 기본 셸>,
}
```

DB 행 없음, 에이전트 레코드 없음. 첫 attach 시점에 세션이 없으면 그때 생성한다(lazy). 서버가 재시작되면 엔진이 세션을 잃으므로 다음 attach에서 다시 생긴다.

ID에 `shell:` 접두어를 두는 이유는 에이전트 id와 같은 공간을 쓰면서도 한눈에 구분되게 하기 위해서다. 접두어 없이 별도 맵을 두면 엔진의 단일 세션 테이블이라는 이점을 잃는다.

## 2. 전송 — 별도 채널

`shell:attach` / `shell:input` / `shell:output` / `shell:resize` / `shell:kill`을 새로 낸다. 이 이벤트들은 `client.watchingAgent`를 읽지도 쓰지도 않는다.

### 왜 `watchingAgent`를 확장하지 않나

그 필드는 **배타적 뷰어 모델**을 떠받치고 있다 — 한 번에 한 기기만 세션을 소유하고, 재접속하면 자동으로 되찾아온다. 아이패드·폰 핸드오프가 자동으로 되는 이유가 이것이다(`ws/hub.go:489`, `:662`의 축출 로직).

여기에 두 번째 세션을 끼워 넣으면 잘 동작하는 메커니즘을 흔들게 되고, 그 실패는 핸드오프가 미묘하게 깨지는 형태로 나타나 재현이 어렵다.

그리고 **스크래치 셸은 애초에 그 의미가 없다.** 배타 소유도, 축출도, 핸드오프도 필요 없고 여러 기기에서 동시에 봐도 문제가 없다. 별도 채널은 회피가 아니라 정직한 모델링이다.

### 반드시 옮겨와야 하는 두 가지

새 채널이라고 해서 다음을 빠뜨리면 안 된다.

- **쓰기 권한 게이트.** 현행 터미널은 "attach된 뷰어만 세션에 쓸 수 있다"를 엔진의 `HasViewer`로 강제한다. 셸 채널도 동일한 검사를 해야 한다. 없으면 아무나 임의의 `shell:<id>`에 명령을 쓸 수 있는 구멍이 된다.
- **ACK 기반 flow control.** 엔진의 `Ack(sessionID, n)`은 대량 출력 시 백프레셔를 푸는 장치다. 클라이언트가 ACK를 보내지 않으면 읽기 펌프가 멈춘 채로 남는다. 셸에서 `yes`나 대용량 로그를 돌리면 바로 드러난다.

## 3. 수명 — 유휴 타임아웃 없음

**규칙은 둘뿐이다.**

- 에이전트를 삭제하면 그 셸도 죽인다 (타임아웃이 아니라 소유 관계)
- 사용자가 명시적으로 종료할 수 있다

**유휴 타임아웃을 두지 않는 이유:** 유휴 판정은 결국 "출력이 없으면 죽인다"로 수렴하는데, **조용한 긴 빌드가 정확히 그 모양이다.** 20분짜리 컴파일을 걸어두고 나갔다 왔을 때 죽어 있는 것이 최악이며, 그것이 바로 이 셸을 유지하기로 한 이유다. 보호하려던 대상을 파괴하는 규칙이 된다.

포그라운드 자식 프로세스 유무로 제대로 판정할 수도 있으나 프로세스 트리를 걷는 플랫폼별 코드가 필요하다. `port_scanner.go`가 정확히 그런 종류의 영리함을 시도했다가 머신 전체를 긁는 결과가 됐다(모든 에이전트에 동일한 25개 포트 표시).

**대신 가시성으로 해결한다.** 셸이 살아 있으면 탭에 표시를 두어 사용자가 쌓인 것을 인지하고 직접 정리하게 한다.

비용은 작다: 프롬프트에 앉은 셸 하나는 수 MB이고 에이전트당 하나로 상한이 걸린다. 옆에서 도는 Claude CLI 프로세스가 훨씬 무겁다. 서버 재시작 때 엔진이 세션을 잃으므로 주기적 청소도 이미 존재한다.

실제로 쌓여서 문제가 되면 그때 **측정값을 갖고** 규칙을 설계한다.

## 4. 화면

**데스크톱·태블릿** — 우측 패널의 4번째 탭. 현행 `rightTab`이 `'subagent' | 'browser' | 'sessions'`이므로 `'shell'`을 더한다. 기존 탭 토글 패턴(같은 탭을 다시 누르면 패널이 닫힘)을 그대로 따른다.

**모바일** — 하단 바텀시트. Files·Browser·Sessions가 쓰는 것과 같은 패턴.

두 경우 모두 기존 터미널 렌더러를 재사용한다. 소프트 키보드가 올라올 때의 뷰포트 처리는 `App.tsx`의 `visualViewport` 로직이 이미 담당한다.

## 5. 에러 처리

- 셸 프로세스가 죽으면(사용자가 `exit`) 패널에 종료 상태를 표시하고 재시작 수단을 준다. 자동 재시작하지 않는다 — 사용자가 의도적으로 나갔을 수 있다
- 엔진이 세션 생성에 실패하면(셸 실행 파일 없음 등) 패널에 사유를 보여준다. 조용히 빈 화면으로 두지 않는다
- 에이전트의 작업 디렉토리가 사라진 경우 홈 디렉토리로 폴백하고 그 사실을 알린다

## 6. 검증

- `cd server && CGO_ENABLED=0 go build ./... && go test ./...`
- `cd client && ./node_modules/.bin/tsc --noEmit`
- 서버 테스트: 쓰기 권한 게이트(attach하지 않은 연결의 `shell:input`이 거부되는지), lazy 생성, 에이전트 삭제 시 동반 종료
- 실제 렌더 확인:
  - 챗을 유지한 채 셸에서 `pwd`가 에이전트의 작업 디렉토리를 가리키는지
  - 패널을 닫았다 열어도 이전 출력과 `cd` 위치가 남아 있는지
  - 다른 페이지를 다녀와도 유지되는지
  - **긴 출력**(`yes | head -100000` 등)에서 멈추지 않는지 — ACK flow control 확인
  - 네이티브 챗의 승인 카드가 셸 사용 중에도 정상 동작하는지 (두 채널이 서로 간섭하지 않는지)
  - **핸드오프 회귀**: 다른 기기에서 같은 에이전트를 열었을 때 배타 뷰어 인계가 여전히 동작하는지
  - 모바일 바텀시트에서 소프트 키보드가 올라와도 입력줄이 가려지지 않는지
  - 셸이 관제실 타일로 나타나지 않는지
- `dist/pcd.exe` 재빌드

## 7. 리스크

| 리스크 | 대응 |
|---|---|
| 새 채널이 배타 뷰어 모델을 우회하다가 기존 핸드오프를 깨뜨림 | 셸 이벤트는 `watchingAgent`를 읽지도 쓰지도 않는다. 검증에 핸드오프 회귀 항목 포함 |
| 쓰기 권한 게이트 누락 → 임의 세션에 쓰기 가능 | `HasViewer` 검사를 셸 채널에도 적용. 서버 테스트로 고정 |
| ACK 누락 → 대량 출력에서 정지 | 검증에 긴 출력 항목 포함 |
| 셸이 에이전트당 하나씩 쌓임 | 탭에 생존 표시 + 명시적 종료. 측정 전까지 자동 종료 규칙을 만들지 않는다 |
| 모바일 바텀시트에서 터미널+키보드가 좁음 | 만들어 보고 판단. 필요하면 전체화면 모드를 추가 |
